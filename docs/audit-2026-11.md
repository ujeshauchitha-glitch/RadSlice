# Audit of the repository, November 2026

Date: 2026-11-10, at commit `eefebb5` (before the restructuring that this audit led to). Method: every claim below
was checked by reading the file or running the command named; where a command was run, its output is quoted.
Severity: **S1** blocks a reviewer from trusting or rerunning the work; **S2** costs credibility or time;
**S3** cosmetic. Items marked *fixed* were fixed on 2026-11-10 in the commits that follow this file; the rest are
decisions for the owner.

## 2. Use case

**One sentence, as the repository now states it:** for a small int8 classifier whose weight memory and accumulators
suffer bit upsets, how much accuracy does each cheap protection keep, at what cost, and which protections fail in
ways a quick analysis would miss.

| # | Severity | Problem | Evidence | Status |
|---|---|---|---|---|
| 2.1 | S1 | The README opened with "two tracks" and a list of fourteen commands; the question was not stated anywhere in one sentence. `docs/goals.md` still has "A radiation-tolerant inference engine for spacecraft" as its `## The goal`, with a note above it saying the note wins. A professor skimming for 60 seconds would come away with the rejected framing. | `README.md` lines 3 to 16; `docs/goals.md` lines 10 to 13 | *fixed* in the README; `goals.md` left as the dated record it says it is, with the moved links updated |
| 2.2 | S2 | **For whom** is not written down. The honest answer, from the council files: (a) people who design small protected inference blocks on FPGAs and want a reproducible accuracy-against-rate comparison with the failure modes shown, (b) the authors of software fault-injection tools (MRFI and the like), who would gain a hardware cross-check, (c) 2D-materials device groups, who would gain a tool for sizing spares, if they supply measured data. None of these has been asked. | `docs/planning/council-2-direction.md` | *partly fixed*: stated in `docs/path-forward.md`; asking is the owner's job |
| 2.3 | S2 | The workload is a 64-32-10 digit classifier (2,368 weights). Every result file says so, but the README did not say how far that is from anything deployed. | `results/g19_baseline.md` | *fixed*: the README limits paragraph says it |
| 2.4 | S2 | The "clean copy" that the strongest results rest on (checksum plus reload, ECC plus reload) is assumed immune and its cost is not modelled; the G20 section says this is "the quantity that decides the trade". That is the single largest unanswered question in the use case and should lead the open-questions list. | `docs/results/g20-weight-protection.md` | open; recorded in the README and `path-forward.md` |
